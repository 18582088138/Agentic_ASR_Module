# 007 · 字幕切不碎：ASR 把静音归给了某个字

**状态**：已修复（`agentic_asr/subtitle/segment.py`）
**发现**：移植上游切分规则后做效果实测，2026-10-04

---

## 现象 / Symptom

把上游那套「按停顿 + 标点 + 字数」的切分规则移植过来后，用真实 faster-whisper 输出实测：

```
原始段数 9　最长一条 16.1s / 13 字
切分后：10 条 | 平均 5.50s | 最长 14.3s   ← max_seconds 设的是 6.0，完全没兜住
```

一条只有 13 个字的字幕，依然挂了 **14.3 秒**。用户要的是「一小段一小段」，这等于没切。

更奇怪的是：**三组差别很大的参数（max_chars=42 / 20 / 14）产出完全一样**。

## 判定 / Diagnosis

分两步查出来的。

### ① 字间停顿全是 0

```
字间停顿（共 95 个）：中位数 0.000s　p90 0.000s　最大 0.000s
  ≥0.28s 的 0 个（强停顿）　≥0.12s 的 0 个（弱停顿）
```

**faster-whisper 的词级时间戳是首尾紧密相连的**（`w[i].end == w[i+1].start`），
它压根不反映真实停顿。所以规则里最核心的「强停顿 / 弱停顿」两条**永远不会触发**。

### ② 静音被归到了某个字身上（真正的坑）

把最长那条段的逐字时长摊开：

```
33.12 ->  34.54  (1.42s)  '开'
34.54 ->  34.82  (0.28s)  '放'
...
35.70 ->  47.38  (11.68s)  '上'      ← 单个「上」字挂了 11.68 秒
47.38 ->  47.66  (0.28s)  '九'
```

**中间那 11.68 秒的真实静音，被 Whisper 记在了「上」这个字上** ——
它把「上」的 `end` 一路拉到静音结束。于是「上」和「九」之间的 gap 依然是 0，
停顿规则**看不见这段静音**，切出来的第一条自然还是十几秒。

⇒ 结论：**不能直接拿 ASR 的字级时间戳当停顿依据**。用之前必须先把「吞了静音的
超长单元」修正掉。上游那份实现没有处理这一点（它直接在 `ASRUnit` 上切）。

## 修法 / Fix

三处，缺一不可：

**① 异常单元钳制**（`_units_from_segment`）：按语速估算单字/单词的合理上限
（`字数 / chars_per_second + 0.4s`），超出的部分**截掉** —— 截掉之后，
多出来的时间就**变成了间隙**，「上」和「九」之间立刻出现 11.38 秒的 gap，
停顿规则这才看得见它。

**② 切分预判**：原来只在「把单元放进 buf 之后」才检查是否超时长，最后一个长单元
会把整条顶穿（能到 `max_seconds` + 单元时长）。改成**入 buf 之前预判**。

**③ 合并不得超限**：`_postprocess` 里「合并过短条目」原本无条件合并，会把上一条
顶穿 —— 实测能到 6.65 s 而 `max_seconds` 是 4.0。加上约束后才真正兜住。

修完的效果：

| | 条数 | 平均 | 最长 |
|---|---|---|---|
| 修复前 | 10 | 5.50s | **14.3s** |
| 修复后 | 10 | 4.16s | **5.5s** ✅ |

## 一个仍然存在的限制（写下来免得以后当 bug 查）

切点偶尔会落在**词中间**（例如切出以「放」开头的条目）。原因是异常单元钳制产生的
间隙位置，取决于 Whisper 那个不准的时间戳，而不是真实的声学停顿。

**要彻底解决，停顿必须来自 VAD，而不是 ASR 的时间戳** —— VAD 直接对音频工作，
它的静音点是声学事实。这条对**没有字级时间戳的场景（TTS）尤其重要**：
那里本来就得靠 VAD 找停顿。

## 回归用例 / Regression

`tests/test_subtitle.py`：

- `test_overlength_unit_becomes_a_visible_gap` —— 造一个「吞了 11 s 静音的字」，
  断言它之后必须被切开，且没有超长条目；
- `test_max_seconds_actually_bounds_cue_length` —— 断言 `max_seconds` 真的兜得住
  （这条最初**是红的**，暴露了合并逻辑的缺陷）；
- `test_numeric_protection_keeps_numbers_whole` —— 数字不被切坏；
- `test_segmentation_trims_leading_punctuation_only` —— 只去开头的悬挂标点。
